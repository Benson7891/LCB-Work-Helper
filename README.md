# LCB Matter 总表

三人跨境律师团队的 Matter 总表。纯静态页面，没有依赖、没有构建步骤，把本文件夹作为仓库根目录推到 GitHub，开启 Pages 就能用。

这个文件夹就是一个可以直接上传的静态站：`index.html` + `styles.css` + `app.js`。

## 语言

导航栏里有 **中 / EN / ES** 三个选项，点了立刻切换，并在这台设备上记住。打开时默认是中文，不跟随浏览器语言（这样妈妈和两位墨西哥同事看到的是同一个起点，谁想换自己点）。界面、状态、日期格式、提醒邮件预览、演示数据都是三语的。

用户自己输入的内容（客户名、事项名称、下一步等）不会被自动翻译——那是团队实际写下的字，翻译反而添乱。

**阶段（Engagement / Due Diligence …）** 在数据里统一存英文原值，界面上按语言显示：中文「立项委托 / 尽职调查 / 法律研究 / 文件起草 / 申报递交 / 政府审批 / 交割结项 / 暂停」，西语「Encargo / Due diligence / Investigación legal / Redacción / Presentación / Revisión de la autoridad / Cierre / En pausa」。**等待谁**（原 Waiting for）的词表同样三语。

**当前阶段**和**等待谁**的下拉最后都有一项「自定义…」：选它就会露出一个输入框，想写什么写什么（比如阶段填「和解谈判」、等待谁填「保险公司」）。自定义的值照原样显示，也会自动出现在事项列表的筛选项里。

## 部署到 GitHub Pages

1. 在 GitHub 新建一个仓库（例如 `lcb-matter-board`），**不要**勾选添加 README。
2. 把本文件夹里的**所有文件**（含隐藏的 `.nojekyll`）放到仓库根目录并 push。
3. 仓库页面 → Settings → Pages → Source 选 **Deploy from a branch**，Branch 选 `main`，文件夹选 **/ (root)**，保存。
4. 等一分钟，访问 `https://<用户名>.github.io/lcb-matter-board/`。

页面用的是 `#/` 形式的地址，刷新和直接分享链接都不会 404，不需要额外的路由配置。

⚠️ GitHub Pages 是公开的：原型里的都是演示数据，随便放。以后要放真实客户信息，得换成私有部署（Cloudflare Access、Vercel 私有、或者自家服务器），不能继续用公开的 Pages。

## 本地预览

直接双击 `index.html` 就能看。如果浏览器是 Safari，本机文件可能不允许保存数据，页面顶部会出提示——换个浏览器，或者在文件夹里执行 `python3 -m http.server 8000` 然后用 `http://localhost:8000` 打开。

## 已经能用的

- 邮箱 + 密码登录（不用短信验证码，海外号码也能进）
- 工作台：红色事项、本周到期、等我推进、可见事项四个数字 + 待处理清单
- 事项列表：按业务类型 / 负责人 / 状态 / Waiting for / 关键词筛选，导出 CSV
- 事项详情：全部字段、项目成员、文件链接、自动记录的操作时间线
- 每周视图：按负责人分组，每张卡回答四个问题，可打印或导出 PDF
- 信息：成员、业务线可见范围矩阵、编号规则
- 新建事项强制校验：客户、事项名称、下一步、截止日期、负责人缺一不可；选黄或红必须写原因
- 删除事项：详情页底部可以删除，走页面内二次确认；删除后进入独立的回收站标签页
- 完成步骤：详情页右侧「当前步骤」卡片，点「完成当前步骤」把这一步推进掉，同时填写新状态——现在这一步要做什么、状态、截止日期、正在等待谁、下一步做什么、下一步负责人、状态说明、当前步骤成员
- 步骤历史：每完成一步都会留在「已完成的步骤」里，写清是谁在哪天完成的
- 撤销到上一步：步骤卡片上有一个「撤销到上一步【上一步的描述】」按钮，误点了就把事项退回那一步——步骤、负责人、截止日期、阶段、状态、成员一起还原，完成记录删掉
- 权限就是事项里的「项目成员」：只有被勾进来的人能打开这条事项，没勾的人连列表和筛选项里都不会出现；直接改地址栏访问也会被拦下
- Carol 是管理员，始终能看到全部事项（保留最终控制权）
- 只有事项的**项目负责人**能删除它：其他人也能看到删除按钮，但点了会提示"只有项目负责人 XXX 才能删除事项"
- 只有**当前步骤负责人**能完成当前步骤：其他人也能看到按钮，点了会提示"只有当前步骤负责人 XXX 才能完成这一步"
- **Carol 是管理员，不受上面两条限制**：她可以代任何事项删除、代任何步骤完成，界面会明确标注"管理员操作"；撤销则留给管理员和刚完成这一步的人
- 从回收站里恢复、或者彻底清掉，只能由该事项负责人操作；已经删掉的事项对项目外的人依然不可见
- 业务类型只决定新建时默认勾谁：Sanctions / U.S. 默认只勾 Carol 与 Carlos，AML 默认 Carol 与 Carlos，其余默认三个人，每条事项都可以单独调整

## 数据是三个人共用的

数据存在 Supabase（免费版）上，三个人看到的是同一份：

- 新建、改状态、完成步骤、删除，都会自动推到服务器；
- 页面每 15 秒自动拉一次最新，切回页面时也会拉，所以别人改的东西最多十几秒就会出现在你屏幕上；
- 顶栏有个 **☁ 已同步** 的小标签，点一下立刻拉最新；断网或推不上去时会变成红色 **⚠ 未同步**，改动留在本机，恢复联网后自动补推。

## 当前安全边界

- 登录使用 Supabase Auth，未登录请求不能读取数据库。
- 数据库按事项的项目成员执行读取权限，Carol 作为管理员可见全部事项。
- 浏览器不再长期缓存事项正文，退出登录时会清除旧缓存。
- 文件目前仍只保存外部链接，不存文件本身；外部链接的访问权限需要在对应网盘单独管理。
